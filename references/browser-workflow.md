# 闲鱼电脑浏览器流程

这些机制已在本机验证；页面、字段、浏览器配置和命令版本会变化。现场状态优先，示例中的名称与 ID 均不是可复用凭证。

## 会话与工具发现

1. 先读本机 `opencli-usage`、`opencli-browser`。用 `opencli list -f json` 筛选 `site == "xianyu"`，避免输出所有站点的巨大清单。
2. `opencli profile list`、`opencli doctor` 检查实际连接。工具报告“Chrome”不证明底层就是 Chrome；本机曾实际运行于夸克。
3. 若报告已连接配置，但连通性仍指向旧的离线配置，使用查到的在线 ID 做**单命令环境覆盖**，例如 `OPENCLI_PROFILE=<当前已连接ID> opencli doctor`。本机曾出现全局 `--profile` 未改变 doctor 探测目标、环境变量覆盖能正确工作的情况。不要改全局默认、不清空配置、不硬编码上次 ID。
4. 连通后运行 `opencli xianyu whoami`。若使用了环境覆盖，本任务后续所有相关 OpenCLI 调用都沿用它，不能只修复 doctor 后又落回旧配置。核对网页实际昵称与用户目标；不把 Cookie 内容输出到聊天、日志或交给陌生脚本。
5. 一个多步骤任务使用一个稳定的浏览器 session；换商品再建独立 session，避免覆盖未完成表单。遇到控件异常优先检查页面，已有充分授权时可用 `cua_repl` 原生 UI 补足。

## 新建与编辑入口

- 新建：`https://www.goofish.com/publish`
- 编辑：`https://www.goofish.com/publish?itemId=<已核实的原商品ID>`
- 详情：`https://www.goofish.com/item?id=<商品ID>`

详情页可能只显示“下架/删除”，个人页也可能没有明显编辑按钮。可以用上面的编辑入口，但必须验证它预填了目标商品的正文、价格和图片；若出现空白新建表单，停止保存并检查，不能因此重复发布。

原生浏览器操作时，站内链接可能打开新标签。OpenCLI 的 session 标签列表可能只包含它拥有的标签。先确认当前 URL；需要原生补充时，在 `cua_repl` 里发现应用/窗口和标签，选择与目标 URL 匹配的表单，不操作用户无关页面。

## 表单适配

较新网页将标题与正文放在同一个 `contenteditable` 描述框，第一行作为标题。旧版发布适配器可能要求独立 title/textarea/condition/category 字段；先查看现场表单及适配器实现/帮助，确认兼容才整条运行。

旧适配器缺乏单独预填或编辑能力、与现场不匹配时，用现有 browser 的结构化 `type/fill/click/upload` 操作填补缺口，不靠猜测字段或执行任意页面写入脚本。

### 文本和数值

- `state` / `find` 后再操作。更改正文、类目或上传图片可能重建字段；重新读取状态与引用，别沿用旧数字 ref。
- `type` 用于空白字段；替换已有文本使用 `fill`，并读回核对。金额用数值字段校验，不只看描述里的数字。
- 富文本 `fill` 可能因为浏览器插入额外空行报告 `verified:false`。检查实际文本和截图：只有空行差异时无需重复插入；内容不同则修复并再次读回。
- 用 Python `subprocess.run([...], env=...)` 传多行正文最稳妥；不要把 `JSON.stringify()` 当 shell 转义，避免反引号、`$()` 意外执行。

### 类目与属性

- 正文/图片会触发自动识别。餐饮代金券可能误识别为“火锅干锅”；实际出售券时，在页面可选项中选择“其他美食优惠券”，填写真实面值与“电子代金券”。
- 自定义组合框可能第一次点击只聚焦；先看是否出现选项，再点下拉箭头或使用键盘选择并确认，随后读回已选值。不要盲目连点或按固定次数上下键。
- 本机某些自定义控件在 OpenCLI 显示 clicked:true 后没有改变；原生 `cua_repl` 可以处理。原生点击也要核验选中值，必要时用当前组合框的键盘操作。
- 电子券选择“无需邮寄”，核验对应单选项已选中。价格自动算出的服务费用于当次收益估算。
- 正确分类仍提示“网页版暂不支持发布此分类”时，保留内容并走页面提供的 APP 接续方式；不更换为无关类别以消除提示。
- 保留用户现有宝贝所在地，不从保存地址列表随意选个人详细地址。

## 图片上传与替换

1. 从实际表单确认 `input[type=file]`、文件类型和多选属性；使用 `opencli browser <session> upload <目标> <绝对路径>`。
2. `uploaded:true`只表示文件注入。等实际缩略图显示及上传完成；图片仍为加载 GIF、错误图或空白时不能提交。必要时截图或只读检查显示中的图片 URL。合理等待后做一次复查；持续无进展时检查具体错误并报告，不无限轮询或反复上传。
3. 替换时先上传新版，确认完成，再移除旧图，保留本地原图。确认最终只剩期望图片和顺序。
4. 本机删除缩略图后会出现“确定要删除这张图片吗？”的确认弹窗；OpenCLI DOM 输出未必包含它。clicked:true 但图片仍在时，查看原生 `cua_repl` accessibility/dialog 状态，处理该**图片**弹窗，不碰商品详情的“删除”。有原图可重新上传的表单替换，不等于删除整条商品。
5. 保留原商品 ID 提交修改，再在该 ID 的详情页核验新图已成为首图、旧图已按预期移除、图片数量和顺序均符合要求。

## 提交与回执

提交前读回：账号、商品、标价及单位、分类/面值/交易形式、交付方式、限制、新图与张数。已授权的单条发布或编辑，核对后提交一次。

等待“发布中”结束并检查详情页。如果超时或中断，先读当前页和用户在售列表，查有无同标题、价格和图片的商品，并结合创建时间、原有商品 ID 和本次跳转/回执排除旧商品。多个相似商品不能唯一匹配时仍属结果不明。合理等待后复查一次仍无进展时报告状态，不无限轮询，不通过再次点击发布来探测。

成功至少需要详情 URL 与商品 ID，加上实际标题、售价和图片相符；修改需要原 ID 不变。保存内容仍在表单时只报告“已填入”，除非页面明确证明已保存草稿。

## 记录可复用信息

当前任务的文案、成品图片、已核实商品链接可以保存在工作区。不要把本次验证码、会话 ID、Cookie、具体券码、某件券的价格/期限写入技能。运行时新增的页面变化，仅在实测后更新这份参考。
